# Player Photos Implementation Plan (Plan 2 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the organizer take or choose a photo for each saved player, and show that photo as a circular avatar on court cards, "Up next", the waiting list, the Setup list and the Saved players screen. Everything stays on the device. Nothing goes online in this plan.

**Architecture:** A new `photos` store in the roster IndexedDB (schema version 2) holds each photo as bytes, written in one transaction with the player row. A pure `processPhoto` function turns a picked picture into a 256 px square JPEG behind a small browser-only interface. `usePhotoUrl(rosterId)` feeds the `photoUrl` prop that `Avatar` already has, and one `PhotoPanel` component runs the take, preview, save flow wherever a photo can be added.

**Tech Stack:** React 18, TypeScript, Vite 6, Zustand 5, idb, Vitest 3 + Testing Library + fake-indexeddb. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-06-pickleball-matchmaking-design.md`, sections "Saved roster (local-first)" and "Photos".

**Follow-ups this plan absorbs:** `docs/superpowers/notes/2026-11-06-follow-ups-and-plan-2-3-prerequisites.md` (the IndexedDB upgrade path, `VersionError` handling, the `blocked` handler, the `usePhotoUrl` hook and `alt=""`).

**Out of scope (Plan 3):** the `outbox` and `syncMeta` stores, Supabase, sign-in, and "Delete all my data". Plan 3 adds them as a version 3 step in the same `upgrade()`.

## Decisions made while planning

1. **Bytes, not Blobs.** A photo is stored as `{ type, data: ArrayBuffer }`. It round-trips in tests, where jsdom's `Blob` does not survive `fake-indexeddb`.
2. **Two ways in.** **Take photo** uses `capture="user"` (front camera, as the spec says). **Choose from library** is a plain picker, because on phones a `capture` input never offers the library.
3. **Setup deviation from the spec.** Setup adds players from a pasted list, so there is no single name field to put an avatar button beside. Each saved-player row in Setup gets an **Add photo** button instead. New names land in that list immediately.
4. **Live Add player.** A new **Add with photo** button saves the newcomer, runs the photo step, then adds them to the session. **Add without a photo** skips the step.
5. **The camera header is a guard.** `capture` hands off to the phone's own camera app, so it should need no page permission. The `Permissions-Policy: camera=(self)` header from the handoff is added anyway and documented as a guard. Task 10 confirms the camera works with it on a phone.
6. **Delete keeps `photoVersion`.** Deleting a player removes the photo bytes but leaves the version, which Plan 3 needs to name the remote file to remove.
7. **No in-memory photo cache.** Each avatar loads its own photo (the spec expects about 15 to 40 KB each). Add a cache only if it is ever slow.

## Rollout

Tasks 1 and 2 change no visible behaviour, so they can be deployed on their own before the photos work. The Plan 1 build has a flaw: when another tab upgrades the database, it steps aside, then reopens at the old version, hits `VersionError`, and shows an empty roster with the "can't be stored" banner. Task 2 removes that flaw. So deploy Tasks 1 and 2 first, then open the app on the phone and tap **Reload now** so it runs that build. After that, the version 2 build can land without the stale tab hitting the flaw. A phone that is still on the Plan 1 build when the photos build ships is not protected.

```ts
/** The schema version this build writes. Bump it, and branch on `oldVersion` in `upgrade`, to change the schema. */
const DB_VERSION = 1;

/** True when the database on disk is newer than the version this build asked for. */
function isVersionError(error: unknown): boolean {
  return typeof error === 'object' && error !== null && (error as { name?: string }).name === 'VersionError';
}

async function openBackend(): Promise<Backend> {
  let database: IDBPDatabase<RosterSchema> | undefined;
  const callbacks: OpenDBCallbacks<RosterSchema> = {
    // Each step runs only for databases older than it, so upgrades work from any earlier version.
    upgrade(d, oldVersion) {
      if (oldVersion < 1) d.createObjectStore('players', { keyPath: 'id' });
    },
    // The browser closed the connection (e.g. iOS Safari when backgrounded): reopen on next use.
    terminated() {
      backendPromise = null;
    },
    // Another tab wants to upgrade or delete the database: step aside and reopen later.
    blocking() {
      database?.close();
      backendPromise = null;
    },
    // An older tab still holds the database open. The upgrade waits until that tab steps aside.
    blocked() {
      console.warn('Saved players are waiting for another tab of this app to close its connection.');
    },
  };
  try {
    try {
      database = await openDB<RosterSchema>(DB_NAME, DB_VERSION, callbacks);
    } catch (error) {
      if (!isVersionError(error)) throw error;
      // A newer build already upgraded the database (a stale tab, or a rolled-back deploy).
      // Open it as it is; the newer schema only adds to the old one.
      database = await openDB<RosterSchema>(DB_NAME, undefined, callbacks);
    }
    return idbBackend(database);
  } catch {
    // Private mode or blocked storage: keep working for this visit, without saving.
    persistent = false;
    return memoryBackend();
  }
}
```

### Task 3: Store photos in the roster database (schema version 2)
Photos go in a new `photos` store, keyed by the roster player id. They are saved as raw bytes plus a type (`{ type, data: ArrayBuffer }`), not as a `Blob`. Bytes round-trip in tests; jsdom's `Blob` does not survive `fake-indexeddb` (checked: it comes back as an empty object). A photo and its player row change together in one transaction, and the transaction is aborted on any failure, so a failed save cannot leave a version number with no picture (a review found that a request that throws on the spot, such as a detached buffer, does not abort a transaction by itself, so the photo request goes first). Deleting a player removes the photo but keeps `photoVersion`, which Plan 3 needs to name the remote file to delete.

```ts
    put: (player) => database.put('players', player),
    async getPhoto(id) {
      const record = await database.get('photos', id);
      return record && { type: record.type, data: record.data };
    },
    async putWithPhoto(player, photo) {
      const tx = database.transaction(['players', 'photos'], 'readwrite');
      // Created first, so aborting below does not leave this promise rejecting with nobody listening.
      const done = tx.done.catch(() => undefined);
      try {
        // Issued first, so a request that throws on the spot (such as a detached buffer) does so
        // before any other request exists. The abort in the catch guarantees nothing is saved.
        await Promise.all([
          photo
            ? tx.objectStore('photos').put({ id: player.id, type: photo.type, data: photo.data })
            : tx.objectStore('photos').delete(player.id),
          tx.objectStore('players').put(player),
          tx.done,
        ]);
      } catch (error) {
        try {
          tx.abort();
        } catch {
          // The transaction had already finished.
        }
        await done;
        throw error;
      }
    },
    close: () => database.close(),
  };
```

```ts
import type { PhotoData } from '../store/rosterDb';

export const PHOTO_SIZE = 256;
export const PHOTO_QUALITY = 0.8;
export const PHOTO_TYPE = 'image/jpeg';

/** Shown to the organizer; the message always says what to do next. */
export class PhotoError extends Error {}

export interface Crop {
  sx: number;
  sy: number;
  side: number;
}

/** The largest square that fits in a width x height picture, centered. */
export function squareCrop(width: number, height: number): Crop {
  const side = Math.min(width, height);
  return { sx: Math.floor((width - side) / 2), sy: Math.floor((height - side) / 2), side };
}

export interface DecodedImage {
  width: number;
  height: number;
  source: CanvasImageSource;
  /** Frees the decoded pixels. */
  release?: () => void;
}

/** The browser-only steps, kept behind an interface so the rest can be tested without a canvas. */
export interface PhotoIo {
  /** Decodes a file into pixels, asking the browser to apply the camera's rotation. Rejects if it is not a readable image. */
  decode(file: Blob): Promise<DecodedImage>;
  /** Draws the cropped square scaled to size x size and encodes it. */
  encode(image: DecodedImage, crop: Crop, size: number, type: string, quality: number): Promise<PhotoData>;
}

function decodeWithImageElement(file: Blob): Promise<DecodedImage> {
  return new Promise((resolve, reject) => {
    const url = URL.createObjectURL(file);
    const img = new Image();
    img.onload = () =>
      resolve({
        width: img.naturalWidth,
        height: img.naturalHeight,
        source: img,
        release: () => URL.revokeObjectURL(url),
      });
    img.onerror = () => {
      URL.revokeObjectURL(url);
      reject(new Error('The picture could not be decoded.'));
    };
    img.src = url;
  });
}

export const browserIo: PhotoIo = {
  async decode(file) {
    try {
      const bitmap = await createImageBitmap(file, { imageOrientation: 'from-image' });
      return { width: bitmap.width, height: bitmap.height, source: bitmap, release: () => bitmap.close() };
    } catch {
      // Older browsers: let an <img> element decode it.
      return decodeWithImageElement(file);
    }
  },
  async encode(image, crop, size, type, quality) {
    const canvas = document.createElement('canvas');
    canvas.width = size;
    canvas.height = size;
    const context = canvas.getContext('2d');
    if (!context) throw new Error('Canvas is not available.');
    // JPEG has no transparency: put a white backdrop under pictures that have it.
    context.fillStyle = '#ffffff';
    context.fillRect(0, 0, size, size);
    context.imageSmoothingQuality = 'high';
    context.drawImage(image.source, crop.sx, crop.sy, crop.side, crop.side, 0, 0, size, size);
    const blob = await new Promise<Blob | null>((resolve) => canvas.toBlob(resolve, type, quality));
    if (!blob) throw new Error('The picture could not be encoded.');
    return { type: blob.type || type, data: await blob.arrayBuffer() };
  },
};

/** Center-crops a picked or captured picture to a square, scales it to 256 px and encodes a small JPEG. */
export async function processPhoto(file: Blob, io: PhotoIo = browserIo): Promise<PhotoData> {
  if (file.type && !file.type.startsWith('image/')) {
    throw new PhotoError('That file is not a picture. Choose a photo instead.');
  }
  let image: DecodedImage;
  try {
    image = await io.decode(file);
  } catch {
    throw new PhotoError("That picture couldn't be read. Try taking it again or choose another one.");
  }
  try {
    if (!(image.width > 0 && image.height > 0)) {
      throw new PhotoError("That picture couldn't be read. Try taking it again or choose another one.");
    }
    return await io.encode(image, squareCrop(image.width, image.height), PHOTO_SIZE, PHOTO_TYPE, PHOTO_QUALITY);
  } catch (error) {
    throw error instanceof PhotoError ? error : new PhotoError("Couldn't prepare that picture. Try again.");
  } finally {
    image.release?.();
  }
}
```

```ts
import { useEffect, useState } from 'react';
import { getRosterPhoto } from '../store/rosterDb';
import { useRosterStore } from '../store/rosterStore';

/**
 * An object URL for a saved player's photo, or undefined when they have none on this device.
 * It reloads when the photo changes and frees the URL when it is replaced or the component goes away.
 */
export function usePhotoUrl(rosterId: string | undefined): string | undefined {
  const version = useRosterStore((s) =>
    rosterId ? (s.players.find((p) => p.id === rosterId)?.photoVersion ?? 0) : 0,
  );
  // Remember whose photo this is, so one player's picture is never shown for another.
  const [loaded, setLoaded] = useState<{ id: string; url: string }>();

  useEffect(() => {
    if (!rosterId || version === 0) {
      setLoaded(undefined);
      return;
    }
    let cancelled = false;
    getRosterPhoto(rosterId)
      .then((photo) => {
        if (cancelled) return;
        setLoaded(
          photo ? { id: rosterId, url: URL.createObjectURL(new Blob([photo.data], { type: photo.type })) } : undefined,
        );
      })
      .catch(() => {
        // A photo that cannot be read just shows initials.
        if (!cancelled) setLoaded(undefined);
      });
    return () => {
      cancelled = true;
    };
  }, [rosterId, version]);

  // The cleanup runs when the URL is replaced and when the component unmounts.
  const url = loaded?.url;
  useEffect(
    () => () => {
      if (url) URL.revokeObjectURL(url);
    },
    [url],
  );

  // Only a photo that belongs to this player, and only while they still have one: a removed photo
  // or a different player's picture disappears in the same render, not after the effect runs.
  return rosterId && version > 0 && loaded?.id === rosterId ? loaded.url : undefined;
}
```

`PhotoPanel` is the whole capture flow in one component: **Take photo** (`capture="user"`, the front camera) and **Choose from library** (a plain picker, because a `capture` input skips the library on phones), then a preview with the permission reminder, **Use photo** and **Retake**. The panel is also used inline inside two other sheets in Task 8, which is why it has no sheet chrome of its own.
```tsx
import { useEffect, useRef, useState, type ChangeEvent } from 'react';
import { PhotoError, processPhoto } from '../lib/photo';
import type { PhotoData } from '../store/rosterDb';
import { useRosterStore } from '../store/rosterStore';
import { PlayerAvatar } from './PlayerAvatar';

interface Props {
  rosterId: string;
  name: string;
  /** Called after a photo is saved or removed, and when the organizer leaves without changing it. */
  onDone: () => void;
  /** The label of the button that leaves without changing the photo. */
  doneLabel?: string;
}

interface Preview {
  photo: PhotoData;
  url: string;
}

/** Take or choose a photo for a saved player, check it, then save it. Remove the current one. */
export function PhotoPanel({ rosterId, name, onDone, doneLabel = 'Close' }: Props) {
  const hasPhoto = useRosterStore((s) => (s.players.find((p) => p.id === rosterId)?.photoVersion ?? 0) > 0);
  const setPhoto = useRosterStore((s) => s.setPhoto);
  const removePhoto = useRosterStore((s) => s.removePhoto);

  const [preview, setPreview] = useState<Preview | null>(null);
  const [busy, setBusy] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const cameraRef = useRef<HTMLInputElement>(null);
  const libraryRef = useRef<HTMLInputElement>(null);
  // The sheet can be dismissed while a picture is being prepared or saved. Once it has, nothing
  // here may create a URL, change state or report "done".
  const alive = useRef(true);
  // Only the latest chosen file may set the preview.
  const latest = useRef(0);
  useEffect(() => {
    alive.current = true;
    return () => {
      alive.current = false;
    };
  }, []);

  // Free the preview's object URL when it is replaced or the panel closes.
  useEffect(
    () => () => {
      if (preview) URL.revokeObjectURL(preview.url);
    },
    [preview],
  );

  async function onFile(event: ChangeEvent<HTMLInputElement>) {
    const file = event.target.files?.[0];
    event.target.value = ''; // lets the same file be chosen again after "Retake"
    if (!file) return;
    const request = ++latest.current;
    const current = () => alive.current && request === latest.current;
    setError(null);
    setBusy(true);
    try {
      const photo = await processPhoto(file);
      if (!current()) return;
      setPreview({ photo, url: URL.createObjectURL(new Blob([photo.data], { type: photo.type })) });
    } catch (e) {
      if (current()) setError(e instanceof PhotoError ? e.message : "Couldn't prepare that picture. Try again.");
    } finally {
      if (current()) setBusy(false);
    }
  }

  async function save() {
    if (!preview) return;
    setError(null);
    setBusy(true);
    try {
      await setPhoto(rosterId, preview.photo);
      if (alive.current) onDone();
    } catch (e) {
      if (alive.current) setError(e instanceof Error ? e.message : "Couldn't save that photo.");
    } finally {
      if (alive.current) setBusy(false);
    }
  }

  async function remove() {
    setError(null);
    setBusy(true);
    try {
      await removePhoto(rosterId);
      if (alive.current) onDone();
    } catch (e) {
      if (alive.current) setError(e instanceof Error ? e.message : "Couldn't remove that photo.");
    } finally {
      if (alive.current) setBusy(false);
    }
  }

  const inputs = (
    <>
      <input
        ref={cameraRef}
        type="file"
        accept="image/*"
        capture="user"
        hidden
        tabIndex={-1}
        aria-label="Take a photo with the camera"
        onChange={(e) => void onFile(e)}
      />
      <input
        ref={libraryRef}
        type="file"
        accept="image/*"
        hidden
        tabIndex={-1}
        aria-label="Choose a photo from the library"
        onChange={(e) => void onFile(e)}
      />
    </>
  );

  return (
    <div className="stack">
      {inputs}

      {preview ? (
        <>
          <img className="photo-preview" src={preview.url} alt={`Preview of the new photo for ${name}`} />
          <p className="muted">Take photos with the player's permission.</p>
          <button type="button" className="btn btn-primary btn-block" disabled={busy} onClick={() => void save()}>
            Use photo
          </button>
          <button type="button" className="btn btn-block" disabled={busy} onClick={() => {
              setError(null);
              setPreview(null);
            }}
          >
            Retake
          </button>
        </>
      ) : (
        <>
          <div className="row-flex">
            <PlayerAvatar name={name} rosterId={rosterId} size="lg" />
            <p className="muted">{hasPhoto ? 'Current photo' : 'No photo yet'}</p>
          </div>
          <button
            type="button"
            className="btn btn-primary btn-block"
            disabled={busy}
            onClick={() => cameraRef.current?.click()}
          >
            {busy ? 'Preparing…' : 'Take photo'}
          </button>
          <button type="button" className="btn btn-block" disabled={busy} onClick={() => libraryRef.current?.click()}>
            Choose from library
          </button>
          {hasPhoto && (
            <button type="button" className="btn btn-block btn-danger" disabled={busy} onClick={() => void remove()}>
              Remove photo
            </button>
          )}
          <button type="button" className="btn btn-ghost btn-block" disabled={busy} onClick={onDone}>
            {doneLabel}
          </button>
        </>
      )}

      {error && (
        <p className="error" role="alert">
          {error}
        </p>
      )}
    </div>
  );
}
```
